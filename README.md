# meta-agent

CLI-агент, который надзирает за другим проектом (`workspace.targetProject` в `meta.config.json`):
строит карту проекта, выбирает релевантные файлы, просит LLM написать патч, применяет его с бэкапами,
прогоняет линтер/тесты и при ошибках пытается исправить сам.

## Запуск

```bash
npm install
cp .env.example .env      # заполнить ключи
npm start                 # интерактивный режим
npm test                  # тесты самого агента
```

Команды в чате: `/run`, `/stop`, `/save`, `/index`, `/abort`, `/redo`, `/clear`, `/editor`, `/push`.
Теги выбора модели в тексте задачи: `@7b`, `@ds`, `@claude`. Файлы подтягиваются через `@путь/к/файлу.js`.

## Защита (что агент НЕ сделает сам)

- Не запишет и не удалит файл вне целевого проекта, а также `.env*`, `.git/`, `.meta-agent/`, `node_modules/`.
- Не применит патч с заглушками вида «остальной код без изменений», с синтаксической ошибкой JS
  или с файлом, сжавшимся более чем на 60%. Патч применяется целиком или не применяется вовсе.
- Не отправит `.env` в облачную LLM.
- Автоматически выполняет только простые команды (`npm install`, `npm test`, `npm run <script>`,
  `git status/diff/log/add/commit`, `node --check`). Всё остальное — только с подтверждением `y`.
  Из Telegram-бота (нет терминала) такие команды отклоняются.

## Telegram-бот (необязательно)

Задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в `.env`, затем `cd meta-bot && npm install && node meta-bot.js`.
