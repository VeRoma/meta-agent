# meta-agent

CLI-агент, который надзирает за другим проектом (`workspace.targetProject` в `meta.config.json`):
строит карту проекта, оркестратор выбирает файлы и исполнителя, исполнитель пишет патч, агент применяет его
с бэкапами, прогоняет линтер и тесты и при ошибках пытается исправить сам.

## Запуск

Рядом с папкой агента должна лежать `../ai-core` (общий пакет `@veroma/ai-core`, github.com/VeRoma/ai-core).

```bash
npm install
cp .env.example .env      # заполнить ключи
npm start                 # интерактивный режим
npm test                  # тесты самого агента (сеть подменяется, ключи не нужны)
```

При старте агент показывает, доступна ли каждая модель из `meta.config.json` (🟢 / 🟡 нет такой модели / 🔴 провайдер недоступен).
Модели задаются только в конфиге.

Команды в чате: `/audit`, `/run`, `/stop`, `/save`, `/index`, `/abort`, `/redo`, `/clear`, `/editor`, `/push`.

## Как выбирается модель

1. Оркестратор (`llm.orchestratorModel`, Gemini) читает задачу и `PROJECT_MAP.md`, выбирает файлы и исполнителя:
   `fast` (DeepSeek, рутина), `pro` (Gemini, большие файлы и несколько модулей), `arch` (Claude, безопасность и сложные алгоритмы).
2. Тег в тексте задачи перекрывает выбор оркестратора: `@ds` / `@deepseek` → fast, `@ge` / `@gemini` → pro, `@claude` / `@cl` → arch.
3. `/audit` никогда не уходит на `fast`.
4. Исполнитель получает исходную задачу и план оркестратора. Если модель просит файлы через `@путь`, их подгрузят (до 3 раз подряд) тому же исполнителю.

Если оркестратор недоступен, задача идёт на `fast` только с файлами, упомянутыми через `@`.

## Защита (что агент НЕ сделает сам)

- Не запишет и не удалит файл вне целевого проекта, а также `.env*`, `.git/`, `.meta-agent/`, `node_modules/`.
- Не применит патч с заглушками вида «остальной код без изменений», с синтаксической ошибкой JS
  или с файлом, сжавшимся более чем на 60%. Патч применяется целиком или не применяется вовсе.
- Не отправит `.env` в облачную LLM.
- Автоматически выполняет только простые команды (`npm install`, `npm test`, `npm run test|lint|build|check`,
  `git status/diff/log/add/commit`, `node --check`, `node --test`). Всё остальное — только с подтверждением `y`.
  Команды с `% ^ & | ; < > $` и подстановками всегда требуют подтверждения (`%VAR%` в cmd.exe раскрыл бы ключи).
  Из Telegram-бота (нет терминала) такие команды отклоняются.
- ESLint и TypeScript запускаются без shell, имена файлов от модели не могут стать командой.
  Нет ESLint, конфига или скрипта `test` — это предупреждение, а не повод «чинить» код.

## Устройство

- `src/config.js` — единственный источник конфига; пути считаются от папки агента, а не от текущей директории.
- `src/core/task-runner.js` — цикл задачи; `context.js` (оркестратор, файлы, теги), `prompt.js`, `executor.js`,
  `commands.js`, `checks.js`. `io.js` — мост к интерфейсу (подтверждения), поэтому движок тестируется без терминала.
- `src/cli/chat.js` — только интерфейс: ввод, команды.
- `src/fs/` — запись патчей, бэкапы, откат. Проверки путей, патчей и команд — общие с dev-agent, из `@veroma/ai-core/safety`.

## Telegram-бот (необязательно)

Задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в `.env`, затем `cd meta-bot && npm install && node meta-bot.js`.
