# Что изменено

## 2026-11-02: гонки в Telegram-боте
- meta-bot выполняет одну директиву за раз (раньше два сообщения подряд запускали два агента на одном проекте).
- Задача передаётся через `META_TASK` в окружении процесса, а не через общий `meta_task.txt`: ручной запуск больше не подхватывает чужую задачу.
- `.meta-agent/agent.lock`: второй Meta-Agent на тот же проект (бот + терминал) отказывается запускаться; lock умершего процесса перехватывается.
- Бот запускает агента без shell (`execFile`).

## 2026-11-02: защита общая с dev-agent (@veroma/ai-core/safety, v1.2.0)
- `safe-path`, `patch-guard`, `command-guard` перенесены в `ai-core`. Копии в двух агентах успели разойтись.
- От dev-agent взяты: секреты `.npmrc`, `*.pem`, `*.key`, `id_rsa`, `credentials.*`, `secrets.*` и защита папок без учёта регистра.
- Белый список команд объединён. `$` и `%` (подстановка переменных) и `npm install <пакет>` всегда требуют подтверждения;
  `npm run` — только `test|lint|build|check`, потому что модель может переписать скрипты в package.json.

## 2026-11-02: переход на @veroma/ai-core, оркестратор, разбор chat.js

### Структура
- `ai-core` вынесен в отдельный пакет `@veroma/ai-core` (github.com/VeRoma/ai-core), подключён как `file:../ai-core`. Относительных импортов `../../../ai-core` больше нет.
- `src/config.js` — один конфиг на процесс. Раньше `meta-agent.js`, `chat.js`, `llm.js`, `session.js`, `patcher.js` читали `meta.config.json` каждый сам, и подмена моделей при старте ни на что не влияла.
- Цикл задачи вынесен из `chat.js` (588 → ~150 строк) в `src/core/task-runner.js` и мелкие модули. Удалены мёртвые `routing.js` и `llm/ollama.js`.

### Безопасность
- command-guard: `%` и `^` требуют подтверждения. Иначе `git commit -m "%GEMINI_API_KEY%"` выполнялся автоматически и cmd.exe записывал ключ в историю git.
- Линтер теперь действительно работает без shell, как было заявлено ниже: раньше имена файлов от модели подставлялись в строку `npx eslint "..."`.

### Баги
- Список файлов из `PROJECT_MAP.md` содержал хвост ` (N lines)`, поэтому `@файл.js` для кода никогда не находился, и подгрузка файлов по просьбе модели не работала.
- Модели больше не подменяются в коде (`gemini-4-argon`): при старте показывается доступность моделей из конфига.
- Пути от оркестратора снова фильтруются по `PROJECT_MAP.md`.
- Исполнитель получает исходную задачу, а не только пересказ оркестратора.
- При авто-подгрузке файлов задача остаётся у того же исполнителя (раньше откатывалась на `fast`).
- Повтор при невалидном JSON идёт на тот же уровень модели, а не на DeepSeek.
- Работают теги `@ds` / `@ge` / `@claude`. `/audit` не уходит на `fast`.
- Если оркестратор недоступен, задача продолжается на `fast` с `@`-файлами вместо падения.
- Нет ESLint, его конфига или скрипта `test` — предупреждение. `node --check` в белом списке (как обещал README).
- Строка-заглушка «далее остальной код без изменений» удалена из `meta-agent.js`.

### Тесты
30 тестов: добавлены e2e цикла задачи с подменённой сетью (оркестратор, теги, лимит подгрузки, падение оркестратора, аудит), проверки линтера без shell и утечки через `%`.

## Безопасность
- `meta-bot/meta-bot.js`: токен и chat id больше не в коде — берутся из `.env` (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`). Добавлен таймаут на запуск агента.
- Новый `src/fs/safe-path.js`: путь от модели обязан лежать внутри проекта (защита от `../`); `.env*`, `.git`, `.meta-agent`, `node_modules` нельзя ни писать, ни удалять; `.env` не читается в контекст LLM.
- Новый `src/core/command-guard.js`: автозапуск только для белого списка; остальное — вопрос `y/N`. Без TTY (Telegram) — отказ.
- Линтер запускается без shell (`node .../eslint.js`), так что имя файла от модели не может стать командой. Редактор открывается только для «безопасных» путей.
- `.gitignore`: `.env.*`, `.meta-agent/`, `.meta_prompt.tmp`, `meta_task.txt`. Добавлен `.env.example`.

## Баги
- `readFilesContent` разрешал пути от cwd, а не от целевого проекта (при `../dev-agent` контекст был пустым). Исправлено, дубли (относительный+абсолютный путь) склеиваются.
- Перевод ответа на русский никогда не срабатывал (`askLocalModel` не экспортировался из `llm.js`). Исправлено.
- Рекурсия «подтяни файл по @» теперь: только новые файлы из карты, не глубже 3, e-mail и теги `@7b/@ds/@claude` не считаются файлами.
- Линтер/тесты: отсутствие ESLint, его конфига, скрипта `test`, упавший запуск ESLint (код ≠ 1) — это предупреждения, а не «ошибки кода» для авто-починки (именно это зациклило агента на `.eslintrc.js`).
- Патчер: «всё или ничего»; проверка на заглушки («остальной код без изменений»), усечение >60%, синтаксис JS. Причина отказа возвращается модели.
- Откат: имена бэкапов `v2~` (раньше `__tests__/a.js` восстанавливался как `/tests//a.js`); созданные в сессии файлы при `/abort` удаляются; после `/abort` бэкапы не «протекают» в следующую задачу; после `/redo` снова доступен `/abort`.
- `buildProjectMap(targetDir)` — патчер раньше обновлял карту не того проекта.
- `meta-agent.js`: убран вызов несуществующего `generateIndexes`, карта строится и при первом запуске, и если её удалили.
- `runner.js`: старый процесс при закрытии обнулял ссылку на новый после рестарта; добавлен антиспам на авто-исправление (+ флаг в `chat.js`, чтобы фиксы не шли параллельно).
- Невалидный JSON от модели: один повторный запрос, ``` внутри строк больше не ломают разбор.
- Диспетчер: пути, которых нет в `PROJECT_MAP.md`, отбрасываются. `llm.js`: при падении локальной модели нет бесполезного повтора на ней же.
- Удалён сломанный `test-fs.js`; устаревшие комментарии про Gemini/Gemma исправлены.
